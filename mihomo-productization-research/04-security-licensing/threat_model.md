# WP-12 威胁模型（简化 STRIDE）— Mihomo 覆写脚本产品化

- 审计日期：2026-10-28（Asia/Taipei）
- 基线：目标仓 HEAD `cc46de0`、上游 HEAD `071d4ec`；依赖清单见 `external_dependency_risk.csv`（DEP-001…034）；WP-1 证据见 `../01-baseline/`
- 证据等级：E4 = 本次实测/命令输出；E2 = 源码直读；E1 = 历史事件记录

## 0. 风险分级定义（与风险登记册 §5.2 口径一致）

风险分数 = 可能性（1–5）× 影响（1–5）；1–4 低、5–9 中、10–15 高、16–25 严重。

- 可能性：1 = 需攻破大厂级账号/基础设施；2 = 需攻破个人维护者账号或特定分发环节；3 = 已有实测故障史或敌手在普通网络环境可为；4 = 已规划动作必然触发或现行恒发生；5 = 已在发生。
- 影响：1 = 仅展示层；2 = 单功能降级且可回退；3 = 多功能降级或测速/选路失真；4 = 分流决策面被控或用户预期被系统性违背；5 = 全部流量决策面（规则/DNS/脚本逻辑）被控。

**结构性前提（贯穿全表）**：覆写脚本本身就是「远程可执行代码」——用户经订阅 URL 引入后，脚本在每次配置生成时以全权改写 dns / proxies / proxy-groups / rules / rule-providers 运行（WP-1 行为目录 §4，E2）。因此本项目最大的信任面不是任何单个规则集，而是**脚本分发链本身**；规则集、Geo 库、图标依次次之。另一结构性事实：整条链上**没有任何内容完整性校验点**——mihomo 的 rule-provider 与 geox 更新机制不提供哈希/签名锚定，客户端对拉到的内容照单全收；HTTPS 只保证「连的是那个域名」，不保证「域名背后的内容没被换过」。章程验收标准特别要求不得把「用了 HTTPS」当作供应链安全方案，本模型据此逐项给出残余风险。

## 1. 威胁清单

### T-01 远程规则集源被篡改（Tampering）— bett-rules 单源控制全量分流规则
- **路径**：appshubcc 账号被盗 / 仓库被接管 / meta 分支被强推 → Go 三件套约 35 处规则集 URL 模板全部派生自单一基址常量（`ruleSetBaseUrl`，Go 主版 L228；ASN 基址由其字符串派生 L230，E4 计数）→ 客户端在 provider interval（86400s）内拉入被篡改的 .mrs 并落盘缓存。
- **影响**：规则内容直接决定域名/IP 落哪个策略组。篡改者可把任意域名（如网银、更新服务器）从直连改道至代理组，或反之把应代理流量改直连暴露。影响 5。
- **现有缓解**：HTTPS 传输；rules-canary 每日巡检——但巡检**只探活（HTTP 状态）不验内容指纹**（E2，巡检脚本行为）；关键金融/Claude 规则有部分手写内联，不完全依赖规则集。
- **残余风险**：高。可能性 2 × 影响 5 = **10（高）**。
- **建议**：① 巡检升级为内容指纹基线：定期抓取关键 .mrs 计算 sha256，与基线 diff 后告警（把「活着」升级为「还是原来那份」）；② 高敏感组（Financial/直连名单）规则尽量内联手写，规则集只作补充；③ 在文档中向用户明示该单点与信任对象。

### T-02 规则集源失效或返回错误数据（DoS / Tampering）— 含镜像抖动与冷启动
- **路径**：源仓删除/改名、CDN 故障或缓存污染、镜像 403 抖动（jsdmirror 2026-10-27 实测分钟级 403，E1/E4 历史记录）。现行暴露面：custom 线与旧 smart 线的 bett 基址仍走 jsdmirror（WP-1 §5 已知漂移，E2）；Go 线已切 raw，但图标（DEP-014）与 Emby/emos 规则（DEP-005/006）仍走 jsdmirror。
- **影响**：热启动时 mihomo 使用磁盘旧缓存（fail-stale：规则陈旧但可用）；**冷启动无缓存时对应规则整体缺失**，流量落兜底规则（MATCH → 默认代理）——本应直连的国内域名改走代理（可用性与隐私双降），本应 REJECT 的广告域名放行（fail-open）。影响 3。
- **现有缓解**：Go 线主源已换官方 raw；客户端缓存机制天然提供 fail-stale。
- **残余风险**：可能性 3 × 影响 3 = **9（中）**。
- **建议**：① 旧线 bett 基址跟进切 raw（消除已知漂移，与 R-002 处置合并）；② 文档标注冷启动依赖：首次导入需联网拉齐规则集；③ 巡检对 jsdmirror 保留观测（其上仍有图标与 Emby 面）。

### T-03 脚本分发链被篡改（Tampering / EoP）— 最高信任面
- **路径**：GitHub 账号被盗、分支被强推、或 jsDelivr/raw 缓存层被投毒 → 用户客户端下一次刷新订阅时拉入被改脚本 → 脚本执行时可任意改写生成配置：替换 DNS 上游为敌手 DoH（解析劫持+查询日志全量观测）、改写规则把流量导向任意组、在组中混入敌手节点（需另备节点凭据配合，脚本本身不能凭空生成可用节点，但可与 T-01 组合完成完整导流）。
- **影响**：影响 5（配置生成权 = 事实上的流量决策权）。
- **现有缓解**：脚本内**无 eval / new Function / require 等动态执行面**（本次全脚本 grep 无命中，E4），即脚本逻辑完全静态可审计；文件头含版本号（`v1.0.0-phase3`）；推送走 Contents API 逐文件小步编辑的既定铁律（流程性缓解，非技术强制）。
- **残余风险**：可能性 2 × 影响 5 = **10（高）**。分支保护设置（禁强推/禁删分支）已向用户给出建议，**是否已实际开启未在本 WP 验证范围内确认**（标为待确认项）。
- **建议**：① 确认并记录分支保护实际状态；② 发布版引入 tag + 固定 commit 链接，与浮动分支链接并行供高级用户校验；③ 重要发布在提交信息中带内容摘要，形成可比对的发布记录。

### T-04 上游自动同步引入回归（Tampering / DoS）— 与 R-005 联动
- **路径**：sync-myclash.yml 每 4 小时无人值守：拉上游 main 的 mihomoScript.js → 与 customPatch.js 拼接 → 直推默认分支 → 主力机订阅自动吃入（SRC-002，E4）。两个放大器：
  1. **customPatch 隐式耦合**：补丁直接引用上游 4 个内部标识符（`rateRegionDefinitions`、`lowRateRegionName`、`urlTestBaseOption`、`iconBaseUrl`，customPatch.js:11-14、45；SRC-107，E2）。上游一旦重命名/重构，补丁静默失效或运行时抛错；
  2. **校验缺口**：sync 的 Validate 步只校验补丁标志串与上游含 `function main(config)`，**不校验上述 4 个标识符存在**（WP-1 差异报告 §2，E2）——耦合断裂不会被现有流水线拦截，会随自动推送直接到达用户设备。
- **影响**：轻则补丁功能（低倍率组追加、DNS 覆盖）静默消失；重则脚本执行抛错，客户端回退到未覆写的原始订阅配置（分流体系整体失效但不易察觉）。上游账号若被盗，此通道还是把敌手代码送进用户设备的自动管道（与 T-03 的区别：T-03 需攻破自有仓，T-04 只需攻破上游或等上游一次坏更新）。影响 4。
- **现有缓解**：事实上的人工精选政策只约束手工维护线，**sync 线仍全自动**；用户主力机正在使用此线（风险敞口为现实而非理论）。
- **残余风险**：可能性 3 × 影响 4 = **12（高）**。
- **建议**：① sync Validate 增加 4 个标识符存在性断言 + 生成后 `node --check` 与合成输入冒烟（WP-1 的 run_variants 方法可复用）；② 同步提交保留上游 commit 标识以便回溯（现已记录标题，建议加 hash）；③ 中长期随双仓方案将 custom 线迁为精选手动同步（与项目总体方向一致）。

### T-05 DNS/路由导致流量走错出口（Spoofing / Tampering）
- **路径**：三条子路径——
  1. **明文 DNS 并列项**：Go 线 direct-nameserver 并列含明文 IP DNS（119.29.29.29、114.114.114.114，WP-1 运行实验确认）。同组竞速以先应答为准，本地网络敌手可抢答投毒 → 国内域名解析被劫持 → 直连分流误判（把代理域名解析到假 IP，或把国内域名导向敌手 IP）。
  2. **DNS 全权覆写的边界误判**：dns 段由脚本全权生成（设计边界），但客户端接管行为因客户端而异（Bettbox override-dns 关时脚本赢，WP-10 领域）；若用户在 App 侧改 DNS 而不生效、或换客户端后接管边界变化，实际解析路径与用户认知不一致。
  3. **引导依赖**：国外 DoH（cloudflare-dns/dns.google）带 `#默认代理` 标记经代理出口解析，代理未就绪时的冷启动解析顺序若处理不当，可致解析失败或回退直连解析（国外查询明文暴露于本地网络）。脚本对 proxy-server-nameserver 有专门处理逻辑（Go L1683-1783，E2），属已有意识的设计，但其行为未在真实客户端全量验证（E5 缺失）。
- **影响**：影响 4（解析面 = 分流的上游决策面）。
- **现有缓解**：国外解析全 DoH 且强制经代理；国内解析 DoH 为主、明文为并列备份；ECS 无关化处理已在 DNS 构建中（WP-1 行为目录）。
- **残余风险**：可能性 3 × 影响 4 = **12（高）**。
- **建议**：① 评估移除明文并列项或将其降为 DoH 失败后的显式兜底（先测延迟代价）；② 在发布文档中画出 DNS 决策图（哪类域名问谁、经哪条路），把「DNS 归脚本」从隐性设计变为用户可见契约（与 WP-6 联动）。

### T-06 真实订阅/凭据泄露进公开产物（Information Disclosure）— 与 R-004 联动
- **路径**：① combo 脚本含个人机场命名逻辑（`[Spark]` 前缀、港/新专属组），若随公开仓发布，等于公开用户的机场构成与使用习惯（隐私面），且其文件头自引用地址公开后任何人可拉取；② 研究/排障过程中把真实订阅 YAML、节点凭据贴入文档、截图、日志或提交历史；③ Git 提交历史长尾：仓库 79% 文件继承上游，但自有文件的历史版本（如旧脚本、已删文件）未做全历史敏感扫描。
- **实测现状（本 WP 扫描，E4）**：研究工作区 + 目标仓脚本本地副本 + phase3 副本范围内，7 类敏感形态（UUID、password 赋值、token/api-key 字段、含 token 参数的 URL、Bearer 头、私钥块、节点 URI）全量扫描**仅命中 1 处**：WP-1 合成夹具的虚构节点密码（server=127.0.0.1，处置=无需处置，建议改占位符防未来误报）。详见 `secret_handling_review.md`。
- **影响**：机场凭据泄露可致账号被盗用/封禁；使用习惯泄露为隐私事件。影响 4。
- **现有缓解**：用户既定边界清晰（combo 仅自用、真实订阅文件存于研究区之外的用户文件区，研究产物只引用其统计数字未复制凭据——扫描无节点 URI 命中与此一致，E4）；章程与本 WP 均执行「只记类型与位置」规则。
- **残余风险**：可能性 3 × 影响 4 = **12（高）**（评分驱动因素是 combo 的结构性存在与未来公开发布动作，而非已发生的泄露——**未发现已发生的真实凭据泄露**，此点须明确）。
- **建议**：① 发布前对公开仓候选文件做与本 WP 同口径的形态扫描并留记录（纳入发布清单）；② 对目标仓做一次全 Git 历史敏感扫描（本 WP 未覆盖，列为后续任务）；③ combo 永不进入公开仓候选集（在发布清单中设为硬门禁）。

### T-07 发布地址指向错误产物 / 版本不可回滚（DoS / Integrity）— 见 DEP-029
- **路径**：脚本订阅地址锚定浮动分支（`@myclash-rules` / 分支名路径），分支即唯一版本通道：无 tag、无 release、无校验和。误推一次坏版本即全量下发，用户端无「回滚到上一版」的手段；仓库/分支改名即全员断链——2026-10-27 用户名改名事件已实证此脆弱性（靠 GitHub 官方重定向续命，旧名一旦被他人注册，重定向即失效，E1）。
- **影响**：影响 3（可用性与发布完整性）。
- **现有缓解**：推送铁律（拉最新底板、小步编辑、推后 API 验证）是流程性缓解；脚本头双地址（jsDelivr + raw）提供通道冗余。
- **残余风险**：可能性 3 × 影响 3 = **9（中）**。
- **建议**：发布版引入语义版本 tag 与「当前推荐版」固定链接；浮动分支链接定位为尝鲜通道；保留上一版本文件副本（如 `archive/releases/`）使回滚成为改链接即可完成的动作。

### T-08 Geo 数据库与面板 UI 的浮动锚点（Tampering）
- **路径**：geox-url 四件套锚定 MetaCubeX/meta-rules-dat 的浮动 `release` 分支（Go L1915-1921，仅缺失时写入，E2）；external-ui-url 锚定 zashboard 的 `releases/latest`（全清单最松的版本锚点，Go L1878-1879，E2）。Geo 库直接参与 IP 规则与 ASN 兜底判定；面板 UI 在本地控制器页面上下文运行，若控制器未设 secret 且在局域网可达，被篡改的 UI 代码可调用控制 API 改配置。
- **影响**：影响 3。
- **现有缓解**：两项均为「缺失才补默认」——已有自备配置的用户不被触及；来源分别为官方生态组织与主流社区项目。
- **残余风险**：可能性 2 × 影响 3 = **6（中）**。
- **建议**：UI 改锚具体 release tag 或不在脚本中预置（多数客户端已自带/可自选面板）；Geo 源保留但在文档标注其浮动属性与数据来源（含 MaxMind 衍生数据，许可面归 WP-13）。

### T-09 Smart GBM 模型供应链（Tampering，低风险有界）
- **路径**：`Smart启用GBM模型` 开关（默认关，opt-in）开启后，内核在无本地模型时按内核默认地址自动下载 Model.bin（vernesong/mihomo GitHub Release 资产）并加载——下载与校验（如有）在内核侧，脚本只置 `uselightgbm=true`（Go-smart L449，E2）。旧 smart 注释还给出 gh-proxy.com 镜像示例（DEP-028），用户照抄启用时模型经不透明第三方中转。
- **澄清**：任务线索提及的 `Model-large.bin` 经全脚本检索**未被本项目任何脚本引用**（E4 无命中），系 echs-top 配置所用文件名；本项目的模型面只有 Model.bin 语义。分析按实际引用展开，不按传闻文件名展开。
- **影响**：模型被篡改只能操纵选路权重（把流量偏向特定节点），不直接取得数据面；下载/加载失败自动回退统计选路（注释明示，E2）。影响 2。
- **残余风险**：可能性 2 × 影响 2 = **4（低）**。
- **建议**：发布版注释删除 gh-proxy 示例或加风险标注；文档说明手动放置模型文件的可信路径。

### T-10 客户端字段被意外覆盖（Integrity / 可用性）— 与 R-008/WP-10 联动
- **路径**：Go 线已用 `{...config}` 铺底 + `=== undefined` 才补默认系统性缓解（WP-1 §4，E2/E4）；但 ① dns/hosts/proxies/groups/rules/profile 属脚本全权覆写（设计边界），用户在 App 内对这些面的修改会被静默覆盖——典型即「Bettbox 设置页改 DNS 不生效」（既定设计，但对不知情用户是预期违背）；② custom 线（上游生成）连接面**无条件赋值**（端口、ipv6、mode 等），用户设置被覆盖是恒发生而非概率事件；③ 顶层 ipv6 的已知缺口：App 设 true 时脚本关不掉（注释明示，属已披露的边界）。
- **影响**：影响 2（以可用性与信任损耗为主，不构成数据泄露）。
- **残余风险**：可能性 4 × 影响 2 = **8（中）**。
- **建议**：发布文档设「脚本接管面清单」一节（哪些字段归脚本、哪些归 App、冲突时谁赢），把隐性边界契约化——这是成本最低、收益最高的信任措施之一（与 WP-10 的分客户端矩阵合并呈现）。

### T-11 健康检查单点（DoS，测速面）— 见 DEP-025
- **路径**：全部 url-test 组共用单一健康检查 URL（apple.com/library/test/success.html，Go L405，E2）。该 URL 不可达、被本地网络劫持或区域性故障时，全组节点同判死亡 → 组切换/不可用；其响应特性（Apple 全球 CDN）也使测速结果带地理偏差。
- **注记**：既有口头设计曾定 cp.cloudflare.com/generate_204，现行 Go 版文件仍为 apple.com——本模型以文件为准（E2 优先于口头记录），差异本身建议在 WP-2/WP-8 处确认是否有意。
- **残余风险**：可能性 2 × 影响 3 = **6（中）**。
- **建议**：评估更换或在文档中标注单点属性；若内核未来支持多 URL 探测再升级。
