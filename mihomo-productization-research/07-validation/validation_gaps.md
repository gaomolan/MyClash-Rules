## GAP-01 运行时验证整体缺位（最大缺口）

- **现状**：本项目全部 E4 证据均为配置生成级。以下事项无一有运行时证据：
  - DNS 运行时全系（WP-6 §8）：EXP-DNS-01（解析路径分离与 D1/D2 决策表运行时核对）、02/05（规则集不可达/陈旧缓存启动）、03（上游黑洞与 F11 形态）、04（节点域名+psn 黑洞冷启动）、07 运行时部分（AAAA 应答与字面地址连接）、08（listen 缺失时裸跑监听行为）；汇总为用例 TC-DNS-08。
  - 规则集故障语义（WP-8 未决项 U-1）：provider 首次下载失败/更新失败的官方语义无文档明示，现以实现通行行为推论（E1）；TC-WP8-01~06 六条故障注入用例待执行。
  - WebRTC/QUIC 运行时命中（U-W7-1/2/3/5/6）：STUN 实际出口、REJECT 命中、私有例外对域名型内网目标的命中、QUIC 对私有 IP 目标的命中、显式 udp:false 节点的内核回退——待 TC-W7-05/06。
  - 性能运行时面（WP-11）：运行时内存、冷启动端到端时延、规则集加载失败的等待与回退未测（生成级数据完备）。
- **影响**：R-002 的故障降级结论、WP-6 的 F11、WP-7 的全部运行时预期目前都是 E1/E2 级推论；发布门禁中 L10 的 P0 项因此无法签核。
- **补齐路径**：搭建内核实验台——官方 mihomo v1.19.33 二进制（Release+sha256 校验、版本钉死）+ 本地 HTTP 桩（provider 替身，可编程返回 404/损坏 mrs/黑洞）+ 替身上游 DNS（CoreDNS 或 dnsmasq，带 `.test` 权威区与查询计数）+ 替身 STUN 服务器 + v6only 记录点。环境规格已散见于 WP-6 §8 与各用例，此处汇总为单一建设任务（归 WP-16 排期第四期）。
- **所需环境**：Linux 沙箱/CI 即可（无需用户设备）；内核二进制引入须走校验和流程（章程 §7.2）。

## GAP-02 引擎矩阵缺两格（R-012）

- **现状**：lookbehind 四引擎中已实证两格——V8（Node 24，6/6 + 全脚本等价）、现代 JavaScriptCore（Bun 1.4.4，6/6 + 输出逐字节一致），见 EXP-WP14-03。缺：
  - **QuickJS**（Bettbox 的 rquickjs 同源系）——恰是主力客户端的引擎，未证前 R-012 不得关闭；
  - **Boa**（Clash Verge Rev 内嵌）——无独立二进制可跑，其 RegExp/lookbehind 支持无公开结论。
  - 附带边界：已证的 JSC 为近期 WebKit；lookbehind 系 Safari 16.4（2023）起支持，老旧设备 JSC 仍可能不支持——不得以 Bun 结果外推旧 JSC。
- **补齐路径**：QuickJS 格——CI 引入 quickjs-ng 官方 `qjs` 二进制（校验和钉死）直接运行 `prototypes/lookbehind_probe.js`（引擎无关写法，已备）；全脚本格因 qjs 无 vm/fs，以「探针通过 + Bettbox 实机全脚本冒烟（TC-C-03）」组合覆盖。Boa 格——在 CVR 实机以最小探针脚本（同探针的 main() 包装）验证，或以 CVR 导入完整脚本观察 changed_keys/报错（TC-C-04 附带）。

## GAP-03 客户端实机层未验证

- **来源**：WP-10 未验证清单 1（Bettbox 脚本失败时 UI 层处置：回退/报错/部分应用——未逐行核到）、2（CVR 设置层与 Script 输出对 dns/mixed-port/tun/sniffer 的逐项最终优先级）、7（Bettbox Compatible 构建与主构建的引擎一致性）、8（全部对象未做实机运行）；U-DNS-3（CVR 与脚本 dns 输出优先级细节，同 WP-10-2）；U-DNS-6（`rule-set:cn` 在 nameserver-policy 的运行时匹配口径）。
- **影响**：R-008（严重）的缓解目前只有源码级（E3）依据；「脚本赢/App 赢」的字段结论在 Bettbox 已源码坐实，但失败路径与 CVR 全面未证。
- **补齐路径**：用户主力机（Bettbox）执行 TC-C-03 冒烟清单（含故意语法错误脚本的失败处置观察，一次即可裁决 WP-10-1）；桌面 CVR 执行 TC-C-04（含设置层逐项对照实验设计）。均为发布前人工项，已写入 strategy §6 门禁。

## GAP-04 Smart 个人分支不可达

- **来源**：WP-10 未验证 4/5/6、R-009。KevinChen222 feat/smart-core 公开不可达（名下 6 个公开仓库无 Bettbox fork；官方 Bettbox 无 smart 分支）；其内核来源、与 lux5am fork 的关系、6 个 Smart GUI 开关现状、其他 smart fork 的参数标签差异（sticky-sessions、lgbm-auto-update 等键的归属）均未验证。
- **影响**：Go-smart 的真实运行环境无法在本项目侧复现；TC-C-05 阻塞；smart 线的全部兼容结论只能以 lux5am fork 源码为基准（TC-K-04）。
- **补齐路径**：由用户确认测试机所用构建的来源（安装包/仓库/版本标识）；若为私有构建，后续以「用户提供版本号+冒烟清单回收」方式登记，不强求源码可达。

## GAP-05 BundleMRS 客户端携带情况不明

- **来源**：WP-8 未决项 U-2。EXP-WP8-02 已证生成输出的 38 个 path-in-bundle 在 meta-rules-dat 的 BundleMRS.7z 中实存 33 个；但 Bettbox 是否随包携带该 bundle 未核实——若不带，手机端冷启动兜底分析不成立，TC-WP8-04 的预期集合随之改变。
- **补齐路径**：检查 Bettbox 安装包内容/运行时目录（用户设备或官方 Release 包体静态检查，后者本项目可先行）。

## GAP-06 DNS 运行时细节三项

- **U-DNS-1**：bett-rules `fakeip_filter` 规则集是否覆盖内核内建默认的微软连通性检测三域名。**可静态补齐**：取得该 .mrs 文件并解码其域名集逐条核对（无需运行时），建议优先做。
- **U-DNS-2**：doh.pub 在引导期实际经 default-nameserver 解析还是经 hosts 钉死命中（内核实现路径）——需 GAP-01 实验台以查询计数裁决。
- **U-DNS-5**：fake-ip-range /15 与 fake-ip-range6 在 TUN/多设备场景的实际影响；dns.ipv6=false 而 fake-ip-range6 存在时 v6 虚拟段是否被使用——需运行时+TUN 环境，部分依赖真机。

## GAP-07 规模与内存上限未测

- **来源**：WP-9 §7-3（仅测至 2000 节点耗时；10000+ 与内存峰值未测）、WP-11（运行时内存未测）。
- **补齐路径**：TC-B-03 在 CI 以合成夹具扩展至 10000 节点并采样进程内存（生成级可先行）；运行时内存随 GAP-01 实验台补。

## GAP-08 夹具代表性边界

- **来源**：WP-9 §7-2（样本为人工构造，误判/漏识别为定性枚举，不构成真实订阅分布下的误判率统计；未采样真实订阅，章程禁止且无必要）、§7-4（combo 交叉场景仅冒烟：[Spark] 信息节点、Spark 重名等未系统覆盖）、§7-5（go-smart 未单独跑套件，以定义逐字一致为代表假设）。
- **补齐路径**：combo 交叉套件与 go-smart 独立套件按 WP-9 同法扩展（CI 可补，纯生成级）；误判率统计一项**不建议补**——需真实订阅采样，与章程的凭据/隐私边界冲突，定性枚举已足够支撑设计决策，此项登记为「接受缺口」。

## GAP-09 Alpha 分支与版本语义未审计

- **来源**：WP-2 未决清单：mihomo Alpha 分支未做源码审计；load-balance 的 hash-key 引入版本文档未标注；组级 routing-mark/interface-name 在 v1.19.33 解析器按「已移除」处理（E3 已证，列此备查）。

- **补齐路径**：源码审计可补（公开仓库只读），排 P3。

## GAP-10 应用级误伤样本未建

- **来源**：WP-7 §3/§8：开关2（屏蔽 STUN 端口）与 QUIC 拦截对语音/视频通话、会议、游戏语音、远程桌面的影响「因应用而异，未逐个验证」；现只有回退方法（关开关），无逐应用清单。

## 缺口 Top3（按对发布决策的阻塞程度）

1. **GAP-01 运行时验证整体缺位**——全部运行时结论（DNS 路由、规则集故障降级、STUN/QUIC 命中、F11）停留在推论级；L10 发布门禁无法签核。
