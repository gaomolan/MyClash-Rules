## 1. 目标架构

**一句话**：产物形态不变（单文件 JS、`main(config)` 入口、开关表为顶层静态字面量），源码形态变为「共享核心单源 + 功能模块 + 功能清单」，由构建脚本按清单拼装出各变体产物；仓库分为公开仓（唯一发布面）与实验室仓（现仓转私有），个人逻辑只存在于实验室仓的私有构建目标中。

**五层划分**：

| 层 | 内容 | 约束 |
|---|---|---|
| 共享核心（core/） | 输入契约、节点管线、DNS 构建、规则骨架、门禁语义、组公共参数——定义域为 WP-5 §3.1 的「必须一致」10 条 | 两版逐字节同源；核心待修清单（含 WP-9 已实锤缺陷）修复一次双版生效 |
| 功能模块（modules/） | 按服务组织：数据表（组名/图标/规则集键/默认策略）+ 构建函数 | 模块间无相互引用，只经核心组装接口挂载；AI 模块的「手写补缺口清单」作为可对账资产纳入断言；Emby 模块保留独立换源点 |
| 功能清单（manifests/） | lite / full 两份清单（外加独立维护的 smart 清单）：模块集合、默认开关、AdBlock 强度档、图标子集 | 即 WP-5 归属表（F-01~F-36）的机器可校验形态；两版默认差异收敛为已声明的 6 开关 + F-20 强度档；归属表改一行，清单与断言必须同步改 |
| 变体派生（build/） | 清单展开 → 块级拼装 → 文件头注入（版本/档位/源 commit/共享段指纹）→ variant 锚点注释 | 只做块级拼装，**不做函数级裁剪**；开关表与服务定义必须展开为顶层静态字面量（引擎硬约束，见 §4）；显式目标白名单，未登记目录直接报错 |
| 个人 overlay | combo 的个人命名逻辑（[Spark] 等） | 只存在于实验室仓，作为私有构建目标；永不进入公开仓候选集 |

**数据流**：上游 sync 改造（落实验室仓候选分支、不直推发布面；Validate 增补耦合标识符断言 + 生成后语法与冒烟检查 + 文件头记录上游 commit hash）→ 精选评审人工合入 → 构建生成 → 三级测试门禁 → 发布（tag 钉版 + 分支版双地址）→ 用户导入 → rules-canary 内容指纹巡检反馈。

**规则集供应链**：只引用、不打包（许可证红线）；官方源优先 + 内容指纹巡检（sha256 + 体积/条目数基线，指纹突变或体积异常告警）+ 分级处置（C 级优先内联或替换、B- 级保留独立换源点、旧线镜像敞口跟进切 raw）。raw 单源的可用性风险为已知接受的残余风险，靠巡检告警 + 备用源清单对冲，本期不建镜像。

**Smart 线**：独立实验线，单独发布、单独标注，不与主线同等承诺；不出 lite 档；参数以 lux5am/mihomo-smart 源码标签为唯一基准逐项核名；LightGBM 保持 opt-in 默认关。降级触发条件（任一成立即启动「弃用回归官方组类型」评估）：fork 停滞超两个主线大版本周期；feat/smart-core 构建被证实与 fork 源码不一致且无法对账；smart 参数语义出现破坏性变更且无迁移路径。

## 2. 路线比较摘要

**代码架构路线（章程 A/B/C/D，13 维度 + 权重 + 敏感性分析）**

| 路线 | 要旨 | 判定 |
|---|---|---|
| A 渐进重构现有派生脚本 | 组织方式不变，逐步清理重复与补测试，底板纪律继续靠人工 | 可行但漂移结构性不可解（R-003 即此路线现状）；其最优子集被 B 的阶段 1 吸收 |
| **B 规格锁定 + 共享核心重写（推荐）** | 先以行为目录 + 一致性清单锁定规格，再抽取单源核心、按清单构建生成；两阶段进入 | 唯一同时满足「结构性单源」「产物形态合规」「归属表可执行化」的路线；HiClash 有同谱系先例（shared 块 + 同步脚本 + golden） |
| C 从零模块化生成器 | 抛开现行代码从数据定义重造 | **否决**：无遥测、无可用 CI（R-001）条件下行为遗漏不可发现，遗漏即静默失效；隐性规格（36 开关两类缺失语义、门禁两分等）极易漏 |
| D 上游薄层补丁 | 以 custom 线为模型，尽量不复制上游 | **否决**：与所有者已定的精选集成政策冲突；无法承载 AI 分组重构等自有演进；customPatch 耦合上游 4 个内部标识符已实证其脆弱性（T-04 评 12 高） |

敏感性：若把迁移成本/技术风险升至最高权重，推荐变为「A 过渡 + B 目标」——正是 B 自带的两阶段形态，推荐不变；使 D 或 C 占优的权重组合分别与既定政策冲突、或需要先有本项目尚不具备的测试基建与反馈通道。**在所有与项目既定政策相容的权重组合下，B 均为首选或与首选等价。**

**仓库拓扑路线（T1~T4，7 维度）**

| 路线 | 要旨 | 判定 |
|---|---|---|
| T1 现仓原地演进 | 一仓到底，靠目录/分支约定隔离 | 次选与回落位：T2 前置未齐或公开意愿撤回时启用 |
| **T2 新公开仓 + 旧仓转私有实验室（推荐）** | 公开仓只放可发布源码/产物/自有资产；旧仓保留 sync、评审与个人构建 | 公开面可审计、个人逻辑结构性隔离；以 R-004 硬门禁为生效前置 |
| T3 双仓双轨长期并行 | 新仓公开、旧仓保持现可见性自用 | 否决：R-004 边界问题永久化，个人逻辑同仓需常驻审计 |
| T4 仅文档化不产品化 | 现仓冻结，只补文档 | 否决：不回应 D-003 的评估命题，R-003/R-005 不设防 |

## 3. ADR-001~004 摘要（全文在 06-architecture/architecture_decision_records/，状态均为「研究建议，待所有者确认」）

- **ADR-001 产物形态与构建生成**：采「共享核心 + 功能清单构建生成」（乙案）。产物保持单文件 + 顶层静态字面量；构建只做块级拼装；文件头含版本/档位/源 commit/共享段指纹。函数级裁剪（丙案）明确推迟——其错误在 CVR 上 fail-open 静默、在 Bettbox 上阻断报错，且当前无可用 CI 兜底；待测试基建成熟后另行 ADR 重评估，不构成路线变更。
- **ADR-002 仓库拓扑**：采 T2，附五项生效前置条件（缺一不可）：① 自有图标先迁入新仓并回读验证；② 引用全量切换至新仓地址并实测；③ 匿名状态下实际拉取脚本与图标成功；④ 新仓许可证卫生完成；⑤ 以上全过后才变更旧仓可见性。前置未齐时事实状态保持 T1，不得以「已决定」为由提前切换可见性。
- **ADR-003 规则集供应链与完整性**：采「官方源优先 + 内容指纹巡检 + 分级处置」，明确否决自建镜像/打包（GPL-3.0 数据入仓即义务翻转，WP-13 红线）。巡检由只探活升级为 sha256 指纹 + 体积/条目数基线（0 字节 .mrs 先例证明 200≠可用）；浮动锚（geox release 分支、external-ui latest）列入收紧评估；bundle 缺失 5 集与 provider 故障语义未明，发布说明不得宣称「离线首启完整可用」。
- **ADR-004 Smart 线定位**：采「独立实验线」（乙案）。单独发布与标注、主线承诺不覆盖 smart；参数基准唯一化（以 fork 源码标签为准，禁抄社区模板未核参数）；不出 lite 档；LightGBM opt-in 默认关且其模型许可未明状态须在实验线文档明示；三条降级触发条件见 §1。

## 4. 防漂移与隔离设计

**防漂移（三级检查为发布门禁，未跑或未 PASS 不得发布）**：
- L0 共享段哈希：core 段在各变体产物中逐字节一致；
- L1 golden 分域对比：必须一致域逐字节比对，允许差异域只做集合差集断言、差集恰好等于声明集（防止合法差异淹没真差异）；
- L2 开关集与默认值断言：36 开关的键集、分类（缺失=开/缺失=关）与默认值逐项断言，两版差异只能出现在清单声明的 6+1 项内。
产物文件头含共享段指纹，供用户报障时对账。影子期机制：构建产物与现行手写版同夹具分域对比、连续周期差异集为空，构建产物才接管发布面；手写版冻结一个周期作回滚源（M-09）。

**隔离设计**：
- 两仓间只允许「精选合入」单向流动；公开仓不含 sync 自动产物与个人构建目标；
- combo 改为实验室仓私有构建目标（overlay + 私有 manifest），构建脚本采用显式目标白名单（未登记目录直接报错）；
- 每次发布对公开产物做个人命名扫描（[Spark]/机场名等 7 类形态，复用 WP-12 扫描集），零命中为常设门禁；
- R-004 顺序写入 ADR-002 生效前置：图标先迁 → 引用切换 → 匿名拉取三方哈希验证 → 才转私有。

**不可妥协约束（任一路线违反即否决）**：① 产物保持单文件 + 顶层静态开关字面量（Bettbox QuickJS extract_options 2s/32MB 只跑顶层、CVR Boa 的硬约束；生成耗时 ≤25 ms 相对 5–10s 限额余量两个数量级，引擎性能不构成方案区分项，产物形态合规才构成）；② 个人逻辑永不进公开仓；③ GPL 数据只引用不打包；④ DNS 安全面不得以「轻量」削减。

## 5. 迁移风险与门禁顺序（M-01~M-12，06-architecture/migration_risks.md）

执行顺序即依赖关系：**M-01 图标迁入 → M-02 重复文件收敛（Cloudflare 双文件字节一致，收敛为单一文件）→ M-03 引用切换（grep 穷举引用清单逐项销账、单独 commit）→ M-04 匿名拉取验证（未登录下 raw/jsDelivr/GitHub API 三方哈希一致、全 200/206、purge 后复测）**；M-08 许可证卫生、M-11 文档三态处置、M-07 sync 加固与移位并行汇入；其后 **M-05 存量过渡期**（旧地址文件头注入迁移提示 + 发布说明迁移三步，长度由 DC-05 定）**→ M-06 旧仓转私有**（执行前最后一轮全量引用终扫含关联仓；低使用时段切换；切换后匿名复测新仓 + 维护者复测 sync 与读取链）；M-10 combo 实验室化与 M-12 Smart 标注为实验室侧收尾；M-09 构建化影子期独立于拓扑迁移、汇合于发布面接管。

**四个一票否决点**（任一命中即暂停迁移、回滚当前步）：① M-04 匿名拉取任一通道哈希不一致；② M-10 个人命名扫描在公开产物中命中；③ M-07 负向演练中 Validate 未拦住构造的坏输入；④ M-09 影子期出现未声明的行为差异。

**顺序错误的唯一用户可见故障点**：先私有化、后切换引用——图标等自有资产的匿名 URL 将立即失效（R-004）。路线图以「阶段 3 结束时旧仓可见性不动、私有化在过渡期满后」的结构性安排排除该顺序错误。存量订阅迁移的残余风险（长期停留旧地址的用户在私有化后静默失效）以过渡期 + 文件头提示 + 发布说明三步对冲，并如实登记、不承诺清零。
