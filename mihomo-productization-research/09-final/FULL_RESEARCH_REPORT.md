## 4. WP-2 官方技术规范（E3，源码直读）

以 Meta-Docs 与内核 v1.19.33 源码建立字段语义卡，与二手资料的多处流行误读做了切割：

- 顶层 `ipv6`（流量面，默认 true）与 `dns.ipv6`（解析面，默认 false，关闭时 AAAA 回空）是两个独立开关；节点 `udp` 默认 false；TUN stack 现行默认为 mips（「默认 system」已过时）；组级 `interface-name`/`routing-mark` 在解析器中是「已移除」而非「已弃用」（写了只报错误日志、不生效）；sniffer `override-destination` 默认为 true（文档示例值 false 是示例不是默认）。
- **两个硬性启动错误**：`dns.enable` 且 nameserver 为空；`respect-rules` 且未配 proxy-server-nameserver——脚本侧均由构造免疫（恒写 enable+nameserver 与 psn，见 §7）。
- **empty-fallback 冲突（R-010）**：官方文档与 v1.19.33 源码 parser 一致禁止填策略组（填组名直接解析报错）；组健康检查 url 只测 proxies 成员、不测 provider 成员。此冲突在 WP-2 范围内无法判定。**结项后裁决（2026-10-28，EXP-R010-01~03）**：官方 v1.19.33 与公开 smart 分叉真二进制实测均拒绝组名回填（同一报错）、parser 源码逐行一致——公开侧处处皆禁；Bettbox 实机观察无法由公开源码解释，残余候选为不可达的私有分支或观察口径，均无法再证实/证伪。R-010 已裁决关闭，DC-02 已拍板兼容开关路线（D-010），见 03-technical-research/r010_adjudication.md。
- 未决项：Alpha 分支未审计、若干字段引入版本与 listen 为空行为查无依据（汇总入 GAP-09 与 U-DNS 系列）。（SRC-1207）

## 7. WP-6 DNS 与解析链路（E4 生成级 + E2）

- 脚本对 DNS 段**全权替换**：恒写 16 键（fake-ip 模式、chinaDNS/foreignDNS 三分工、follow-policy=true 等）；输入配置的 nameserver-policy/hosts 只被定向打捞——与节点域名相交的 policy 被收入 psn-policy 且后缀被静默剥离改直连，输入 hosts 只作节点改写数据源、从不进输出。
- **国外链单链架构（F11）**：无 fallback、无 respect-rules，两条 DoH 以 `#默认代理` 后缀出站；默认代理组无可用节点时国外解析整体中断、脚本内无兜底，国内链独立存活。引导依赖靠纯 IP 的 default-nameserver 与 hosts 钉死打破循环（U-DNS-2 的实际命中路径未实测）。
- 与官方默认的显式偏离均已登记：cache-algorithm 用 arc（官方默认 lru，脚本未附选择依据）、fake-ip-range 用 /15（内建默认 /16）；fake-ip-filter 整体替换后，内核内建的微软连通性三域名是否被 bett-rules 规则集覆盖未逐条核对（U-DNS-1，可静态补齐）。
- 附带发现：`baseRuleProviders` 中 `cn` 键在 L366/L387 重复定义（内容相同、后者静默覆盖前者），属编辑陷阱，已转 WP-14 以豁免清单 + 静态检查处理。
- 与 ISSUE-002 的印证：健康检查 URL 的现行代码值确为 apple.com（与 2026-10-16 的 generate_204 决策记录漂移），WP-8 补充了其结构理由（直连成员需同尺可测），口径统一留待所有者二选一（BL-114）。（SRC-1212）

## 8. WP-7 IPv6 / UDP / WebRTC / QUIC（E4 生成级）

- 双开关四组合真值表经生成级实测：两开关生成层面零相互干扰（开关 2 增量恒为 +10 条规则、位置恒定）。
- **开关 1「WebRTC 走代理」不生成任何路由规则**：其实质是 ipv6/udp 铺垫三件套（补缺省 udp、dns.ipv6 与逻辑压制、输入未设时写顶层 ipv6=false）；STUN 实际出口走普通规则链、最终落点是用户可切换的「漏网之鱼」组，出口不由脚本锁定。
- **IPv6 缺口复现**：输入顶层 ipv6=true 时，脚本（以及该开关）关不掉它，最终靠 Bettbox App 层兜底；脚本自身可产出「解析开、流量关」组合。dns.ipv6 由「IPv6 总开关 && !WebRTC 走代理」与逻辑决定——用户单开总开关而 WebRTC 开关在场时，DNS IPv6 依然关闭，与开关名的直觉相反。
- **QUIC 与 STUN 的私有地址例外不对称**：STUN 段有 5 条 private_ip 例外先行，QUIC 规则没有——UDP/443 指向私有 IP 可能先于兜底直连被 REJECT（E2 规则序推导，U-W7-3 待运行时证实）。STUN 端口屏蔽只能覆盖「以常见端口联系已知服务器」一段，不得宣称阻断全部 WebRTC（覆盖边界结论）。（SRC-1213）

## 9. WP-8 规则、代理组与规则集（E4）

- **引用完整性实测全绿**：自研校验器以 7 种合成场景 × 三件套运行 main() 后校验——悬空引用 0、空组 0、循环引用 0、孤儿规则集 0、重复名 0；关组场景下组 + 规则 + provider 同步消失、三联动门控成立；combo 的 Spark 隔离经计数互证无泄漏。空池输入时脚本显式抛错拒绝生成残缺配置（fail-fast，上游同源行为）。
- **单地区降级缺口**：仅有单地区节点时 4 个组的 default-selected 指向未生成组，按 wiki 语义静默回退首个成员，不报错但设计意图失效；已给出生成时校验建议（未实施）。
- **规则集可靠性分级**（38 个 provider，全 mrs/86400s）：A- bett-rules via raw（34 个）：每日发布、官方通道，扣分在单仓单通道集中度与 4 个 bundle 路径缺失；B AWAvenue via jsDelivr：jsDelivr 有 50MB 拒仓先例且其 bundle 路径不存在、冷启动无兜底；B- Emby/emos via jsdmirror：镜像有 403 抖动实测记录，且 bundle 兜底加载的是 meta-rules-dat 的同名集、与远端原文不等价（隐性语义替换）；C cn_additional via 个人域名：无仓库无版本锚点，但仅用于 QUIC 豁免子句、失败方向温和，是全表爆炸半径控制最合理的一处。BundleMRS.7z 对 38 个路径实测命中 33，缺失 5（fakeip_filter、microsoft_ip、apple_ip、tiktok_ip、avenue-ads）。即时探活 39/39 返回 206 仅为 E1 快照，不构成长期结论。
- 健康检查：全组共用 apple.com 测活地址、interval 600、empty-fallback 为 REJECT（合规值）；expected-status 未设，「劫持型假活」不被识别的风险已登记为建议项。（SRC-1214）

## 10. WP-9 节点识别与标准化（E4）

五步管线（类型剔除 → 不可见字符剥离 → 地区/倍率双轨识别 → 过滤 → 标准化改名与引用修复）以 135 例合成夹具 + 66 条正则单元矩阵全量实测，发现 F-01~F-21（完整清单见 TECHNICAL_FINDINGS.md）：

- 漏识别：繁体字形全线漏（覆盖面最大）、英文城市名不收、名单外城市不收、旧线台湾名单弱于 Go 线。
- 误判：`x86`→×86 高倍率、`v0.5`→低倍率、`0.55` 前缀误吞（设计边界 ≤0.5）、高倍率正则缺信息词守卫（与低倍率侧不对称）。
- 静默行为：标准化碰撞整节点丢弃（三种碰撞形态）、零宽变体绕过去重、dialer 目标失效时静默删引用、ip-version 偏好覆写节点显式值、私有 policy 后缀静默改直连（WP-6 交叉）。
- 健壮性：name 缺失/数字/null 使 main() 抛 TypeError 全盘失败、无降级；含 proxy-providers 的输入在入口直接抛错（架构边界，非缺陷）。
- 跨线分叉：倍率判定 Go 线与上游系不一致（1.1x/1.5倍 仅 Go 判高倍率）；customPatch「台湾省」组名 bug 以运行实测复现（台湾低倍率组永不生成）。
- 性能：200 节点 3.2–3.6 ms、2000 节点 27.5–32.3 ms，生成耗时不构成瓶颈。（SRC-1215）

## 11. WP-10 客户端与内核兼容性（E3 源码级，无实机）

- **Bettbox**（v1.19.7）：三段式流水线——QuickJS（rquickjs）脚本段（extract_options 2s/32MB 只跑顶层提取开关表，evaluate 10s/128MB，GUI 选择以 Object.assign 回注脚本全局）→ Go applyPatch 段（general 段 App 赢、DNS 仅 override-dns 开启时 App 赢、sniffer 整体替换）→ 内核段。2026-10-16 的四项旧审计结论经当前 HEAD 复核全部仍成立，且接管面比旧结论更宽。
