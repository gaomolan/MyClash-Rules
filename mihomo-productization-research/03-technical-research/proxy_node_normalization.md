## 1. 机制说明（Go 主版为基准）

节点处理是一条五步管线（`filterAndNormalizeProxies`，L965-1043）：

1. **类型剔除**：`proxies` 中 `type` 为 direct/reject/rematch 的条目先被删除（与用户手写与否无关）。
2. **匹配名归一**：`toMatchableName`（L888）用 `invisibleCharsRegex` 剥离 22 类零宽/不可见字符（软连字符、蒙古元音分隔符、ZWSP、左右方向标记、Bidi 控制、词连接符、韩文填充、BOM、全角空格等）——**仅用于匹配，不改写输出名**。
3. **双轨识别**：`getMatchedRegions`（L893）对匹配名跑 `allRegionDefinitions` = 5 个地区定义 + 2 个倍率伪地区（低倍率节点/高倍率节点）。一个节点可同时命中多个地区（多重归属）；结果按原名缓存（`regionMatchCache`）。
4. **过滤**（顺序敏感）：
   - 倍率过滤开关开启时，命中对应倍率正则的节点被删（默认关）；
   - 「过滤非地区节点」开启时（默认开），节点保留条件 = `命中真实地区 || !excludeFilter.test(匹配名)`。即：**有地区者豁免信息词过滤；无地区者命中任一信息词即删；无地区且不含信息词者保留**，进入「其他节点」组。
5. **标准化与引用修复**：`normalizeProxyName`（L909）提取已有国旗（`flagRegex`）置于名首、无旗则按首个命中地区补旗、折叠多余空白；**改名后按名去重（先到先得，后到者整节点静默丢弃）**；`fixDialerProxy`（L932）按改名图更新 dialer 引用、目标不存在则**删除该引用**；最后 `getIpVersionPreference`（L953）在恰一开关开启时统一改写全部节点 `ip-version`。

组生成（`buildRegionGroups` L1096 / `createRegionGroup` L1045）：每地区生成手动组 + `-Auto`（url-test），低倍率成员另生成隐藏的 `-Eco-Auto` 并挂入地区组选项；倍率伪地区生成「低倍率节点/高倍率节点」组（显示开关只控 hidden）；无地区节点进「其他节点」组。自定义（自建）节点走独立通道：不参与上述过滤、重名时加「自建-」前缀（`buildCustomizeGroups` L1143）。

### 2.2 变体差异（E2 静态比对 + E4 实测）

- **Go 三件套**：定义逐字一致（本 WP 全部结论对三者同等适用；combo 的 Spark 分流在过滤之后按 `[Spark]` 前缀另行切分，与识别正则无关，S11 冒烟通过）。
- **旧 smart**：组名为旧称（香港/台湾）；**无 toMatchableName**（`getMatchedRegions` L903 直接测原始名）；美国名单含「圣地亚哥」、不含 Go 的取舍；台湾名单无新北/桃园/新竹/hinet；RATE-LOW 后顾为 `(?<!\d)`（无小数点防护）；RATE-HIGH 仅整数 ≥2（无 1.x 小数分支）。
- **custom（上游+customPatch）**：定义与上游一致——台湾名单同旧 smart 的弱版、无 hinet；RATE-HIGH 同旧 smart 弱版。customPatch（107 行）本身不定义正则，复用上游 `rateRegionDefinitions` 按组名追加低倍率组，其地区名单硬编码含 **「台湾省」** 而上游组名为「台湾」（见 F-15）。

## 4. 发现清单（误判 / 漏识别 / 行为风险）

> 影响面标注：全线 = Go 三件套 + 旧 smart + custom/upstream 均实测命中；其余注明。

- **F-01 繁体字形漏识别（全线，E4）**：`台灣`、`臺灣`、`美國` 不命中任何地区（正则只有简体 台湾/美国），节点落入「其他节点」。繁体是港台机场的高频命名，此为覆盖面最大的漏识别类。
- **F-02 英文城市名漏识别（全线，E4）**：Tokyo、Osaka、Los Angeles、Dallas 均不命中（日/美正则只收中文城市名 + 国家英文名）。英文全名命名的订阅整批落入「其他节点」。
- **F-03 名单外城市漏识别（全线，E4）**：台中（台湾名单仅台北/高雄/新北/桃园/新竹）、达拉斯等未收录城市同 F-02 后果。
- **F-04 `x86`/`x64` 高倍率误判（全线，E4）**：RATE-HIGH 前缀分支 `[符号x]([1-9]\d+)` 使「香港 x86 优化」被判高倍率（×86），进入高倍率组；开启「过滤高倍率节点」时会被误删。
- **F-05 版本号 `v0.5` 低倍率误判（全线，E4）**：「香港 v0.5 测试」被 RATE-LOW 的 `0.[0-5]` 分支命中，进入低倍率组与 Eco-Auto。
- **F-06 `0.55` 边界误判（全线，E4）**：`0.55x` 被前缀匹配 `0.5` 判低倍率；正则只约束首位小数，0.51–0.59 全部误入（设计边界为 ≤0.5）。
- **F-07 高倍率正则无信息词守卫（全线，E4）**：RATE-LOW 有 `(?!.*(剩|期))` 守卫，RATE-HIGH 没有——「香港 到期2倍」被判高倍率。守卫不对称使带倍率数字的信息文案在高倍侧漏网。
- **F-08 信息词与地区名共存时信息节点存活（全线，E4）**：「香港 剩余流量提示」「日本 官网验证」因地区豁免被保留并进入地区组。机场若以「地区+状态」命名公告节点，公告将混入地区组（与 F-09 互为镜像：过滤只对无地区名生效）。
- **F-09 非地区真实节点误删（全线，默认开关，E4）**：无地区名的真实节点只要含任一信息词即被删——实测「公益免费节点 01」「国内中转 01」均被过滤。excludeFilter 含 公益/国内/公益 等宽泛词，约 90 词的词表使误删面随命名习惯放大；被删无任何日志/提示。
- **F-10 标准化碰撞静默丢节点（Go 系实测，E4）**：三类碰撞均使后到节点**整节点丢失**（含其不同 server/port）：①完全同名；②旗帜差异（`🇭🇰 香港 02` 与 `香港 02` 归一同名）；③空白折叠（`香港  03` 双空格与 `香港 03`）。去重无警告，订阅侧两个不同服务器只剩其一。
- **F-11 零宽变体绕过去重 + 旧线零宽漏识别（E4）**：Go 系中 `香港 04` 与 `香\u200B港 04` 因输出名保留 ZWSP 而不触发去重，视觉同名双节点并存（与 F-10 相反方向的不一致）；旧 smart 无剥离机制，`香\u200B港 01` 整词漏识别落入「其他节点」。
- **F-12 dialer-proxy 目标失效时静默删引用（E4）**：目标被过滤（信息节点）或不存在时，`fixDialerProxy` 直接删除引用，链式节点静默降级为直连出站，无提示。（目标被改名/目标为重复被删节点时，引用可正确跟随改名图——正例已验证。）
- **F-13 ip-version 偏好覆写用户显式值（E4）**：默认「代理IPV4优先=true、IPV6优先=false」时，节点显式 `ip-version: ipv6` 被统一改写为 `ipv4-prefer`。此为开关设计语义（注释明示），但与 Go 线「读现有值、缺失才补默认」的连接面哲学存在张力：节点字段不在该哲学的豁免清单内。双开或双关时不覆写（S7b 实测保留）。
- **F-14 倍率判定跨线分叉（E4）**：`1.1x`、`1.5倍` 仅 Go 系判高倍率；旧 smart/custom（上游系）不判。同一订阅在主力机（custom 线）与 Go 线下倍率分组不一致，用户跨设备对照会困惑。
- **F-15 customPatch「台湾省」失效实测复现（custom 线，E4）**：补丁硬编码组名集合含「台湾省」，上游组名为「台湾」，故 custom 线的「台湾-低倍率自动选择」组**永不生成**（S10c：香港/日本补丁组正常生成、台湾缺席）。Go 线已以地区注册表比对修复此问题（行为目录 §2 已载），本 WP 以运行实测复核确认。
- **F-16 错旗保留的显示不一致（E4）**：`🇺🇸 香港 01` 按文字归入中国香港组，但标准化保留原 🇺🇸 旗（原旗优先规则），组内出现旗帜与归属不一致的节点名。
- **F-17 多地区多重归属（特性登记，E4）**：「香港转美国 01」同时进入中国香港与美国两组（含各自 Auto）。中转/落地复合命名场景下属可解释行为，但同一节点在多组重复出现可能非用户预期，登记为特性而非缺陷。
- **F-18 圣地亚哥三线三结果（争议，E4）**：Go 已移除（现落入「其他节点」）、旧 smart 保留判美国、custom/上游不含。地名本身歧义（智利首都同名），Go 的移除是已记录的取舍；三线结果不一致属迁移期现象。
- **F-19 台湾名单新旧线差（E4）**：hinet、新北、桃园、新竹仅 Go 名单命中；旧 smart/custom 对应节点漏识别。
- **F-20 「下载」借用低倍率语义（E4）**：含「下载」的节点（且不含客户端/软件）一律判低倍率——与倍率无关的语义借用，源自上游设计（下载类节点通常为低倍/免费通道的经验规则）。守卫实测有效（「客户端下载」不命中）。
- **F-21 畸形 name 使整份覆写崩溃（E4）**：name 缺失、为数字或 null 时 `normalizeProxyName` 抛 TypeError，main() 整体失败、无降级；空字符串名则被静默保留进「其他节点」。订阅源单个坏条目即可用性影响全配置。

**已验证的正例（防误判设计有效）**：`Russia` 的 us 子串被字母边界后顾拦截；`10.5x` 不被低倍率误吞（小数点后顾）；`Freedom` 不命中 free（词边界）；`1x`/`1.0倍` 正确归标准倍率；`0.6x` 落标准空档（0.6–1.0 无倍率组，属设计）；`剩余0.5倍` 被剩/期守卫挡住；空节点列表与全过滤场景抛明确错误而非静默输出空配置；dialer 改名跟随与目标在册保留均正确。

## 5. 字段兼容与引用完整性结论

- **未知字段保留（E4）**：节点对象全程以展开复制流转，实测未知字段（嵌套对象 `x-future-field`、自定义键 `x-note`）原样保留，无白名单重建丢弃。与 WP-1 §4 源码结论互印。
- **定向改写面**：仅 name（标准化）、dialer-proxy（F-12）、ip-version（F-13）、udp（main 的 WebRTC 修复：`udp === undefined` 才补 true，显式 false 实测保留）四处。
- **引用完整性**：改名图覆盖「改名跟随」与「被删重复节点的引用收敛」；缺口在 F-12 的静默删除与 F-10 的静默丢节点——两者都不产生悬空引用（不会生成指向不存在节点的组/引用），代价是行为静默改变。
- **proxy-providers 形态**：脚本对含 proxy-providers 的 config 在 main 入口直接抛错（WP-1 §1），故 provider 节点不经过本管线——识别/标准化对该形态**不适用**，属架构边界而非缺陷。

## 6. 性能（EXP-903）

200 节点 3.2–3.6 ms、2000 节点 27.5–32.3 ms（Go 主版，含全部组/规则/DNS 生成）。`regionMatchCache` 使同名重复匹配零成本；2000 节点量级下生成耗时不构成冷启动瓶颈。内存峰值未测（见 §7）。

## 7. 未覆盖项与限制

1. **客户端 JS 引擎差异未测**：全部正则大量使用 lookbehind（`(?<!…)`、`(?<=…)` 在归档版）与 Unicode 属性——V8 实测通过不等于 Bettbox/Clash Verge Rev 实际引擎（JavaScriptCore/QuickJS 系）全部支持；旧版 JavaScriptCore 不支持 lookbehind，可能整脚本失效。此为兼容性高风险项，建议 WP-10/WP-14 在真实客户端验证，本 WP 仅登记（E0，无实测）。
2. **样本为人工构造**：66 条单元 + 135 条套件用例覆盖的是「机制与边界」，误判/漏识别为定性枚举，**不构成真实订阅命名分布下的误判率统计**；未采样任何真实订阅（章程禁止且无必要）。
3. **内存与超大规模未测**：仅测至 2000 节点耗时；10000+ 节点与内存峰值未测。
4. **combo 交叉场景仅冒烟**：Spark 切分与倍率/过滤的交叉（如 [Spark] 信息节点、Spark 重名）未系统覆盖，combo 与 Go 定义一致使风险有限。
5. **go-smart 运行行为未单独跑套件**：其定义与 Go 逐字一致（E2），套件以 Go 为代表；Smart 组型差异属 WP-10 范畴。
6. **「设计意图」含研究者判定**：覆盖矩阵中意图列为按注释/命名惯例/上游沿革的判定（如「下载→低倍」记为设计借用而非误判），个别条目可争议，已在备注中标明依据。
