```

  上游 AIsouler/MyClash │  实验室仓（现仓转私有）                          │

┌──────────────────────────────────────────────────────────────────────────────────┐
│  公开仓（新仓，唯一发布面）                                                        │

│   ├─ modules/     功能模块（按服务组织的数据表 + 构建函数）：AI/Claude/GitHub/…    │

│  tests/           L0 共享段哈希 / L1 golden 分域对比 / L2 开关集断言 / 引用完整性 │

└──────────────────────────────────────────────────────────────────────────────────┘
        │ 发布门禁（§4）                        │ 规则集（不入仓打包，URL 引用）

  用户导入（Bettbox / CVR）            规则集供应链（§3）：官方源优先 + 指纹巡检
```

三个结构性决定（详见 ADR）：

1. **产物形态不变、源码形态变**：发布物仍是单文件 JS、入口 `main(config)`、开关表为顶层静态字面量——这是 Bettbox QuickJS `extract_options`（2s/32MB，只跑顶层提取）与 CVR Boa 的硬约束（SRC-1008），任何架构不得突破。变化发生在仓库内部：源码拆为共享核心 + 功能模块 + 功能清单，由构建脚本拼装产物（ADR-001）。
2. **仓库双分**：新建公开仓只放可发布产物与源码；现仓转私有作实验室（上游同步、精选评审、个人构建目标）。公开/私有之间只允许「精选合入」单向流动，个人逻辑永不进入公开仓候选集（ADR-002，R-004 硬门禁）。
3. **规则集只引用、不打包**：新仓禁止镜像/打包 GPL-3.0 数据文件（义务翻转红线，SRC-1017）；供应链靠「官方源优先 + 内容指纹巡检 + 分级处置」加固（ADR-003）。

## 1. 模块划分

### 1.1 共享核心（core/）——单源，两版逐字节一致

定义域 = WP-5 §3.1 的「必须一致」10 条（SRC-1004），逐项落位：

| 核心组件 | 内容 | 证据/约束来源 |
|---|---|---|
| 输入契约 | `{...config}` 铺底透传；含 proxy-providers 即抛错终止；external-controller/secret 不写 | WP-1 行为目录（转引自 SRC-1004 §3.1.1） |
| 配置哲学执行层 | 连接面字段「缺失才补默认、已设尊重」；端口类故意不补的既定取舍 | WP-5 §3.1.2 |
| 节点管线 | 不可见字符剥离 → 地区/倍率双轨识别 → 过滤 → 标准化改名 + renameMap + dialer 修复；未知字段原样保留 | WP-9 管线实测（SRC-1012 §1/§5）；已知缺陷（繁体漏识别、误判、碰撞静默丢弃、畸形 name 崩溃）为核心待修清单，修复一次双版生效 |
| DNS 构建 | fake-ip 全套语义、nameserver 三分工、policy 合并而非替换、引导不依赖被代理域名 | WP-6（SRC-1009）；DNS 为章程级安全面，禁止以「轻量」削减 |
| 规则骨架 | prefixRules → STUN 段 → QUIC 段 → 服务规则 → 兜底五条的相对顺序 | WP-8 优先级实测（SRC-1011 §1/§2，默认输出 96 条构成） |
| 门禁语义 | 「`=== false` 才跳过」与「缺失=关」两分分类，同名开关分类两版一致 | WP-5 §3.1.6；2026-10-20 门禁事故为历史依据 |
| 组公共参数 | groupBaseOption 家族（健康检查、interval、empty-fallback 等） | WP-8 §4（SRC-1011）；empty-fallback 受 R-010 约束（§5） |

### 1.2 功能模块（modules/）——按服务组织

每个服务组一个模块：数据表（serviceConfigs 式：组名/图标/规则集键/默认策略）+ 构建函数。模块间无相互引用，只能经核心的组装接口挂载——这是防漂移的结构前提：模块增减不改核心。

- AI 模块须内含「手写补缺口清单」（category-ai-!cn 之外的 qwen.ai/z.ai/auth0.com 等）作为**可对账资产**：清单漂移会同时打穿两版（WP-5 §4 F-07 加注），须纳入 L2 断言范围。
- Emby 模块保留独立换源能力（其 666OS/emos 双个人源是全矩阵最弱依赖环，SRC-1011 分级 B-；WP-5 §1.3）。
- Financial/Cloudflare 模块标注「风控敏感簇」，默认策略与 Spark 备选关系在模块元数据中声明，不散落代码。

### 1.3 功能清单（manifests/）——归属表的可执行形态

lite / full 两份清单声明：模块集合、每模块默认开/关、AdBlock 强度档、图标子集。清单即 WP-5 §4 归属表（F-01~F-36）的机器可校验形态：**归属表改一行，清单与 L2 断言必须同步改**，文档与代码从此不能静默分家（WP-5 §5 L2）。两版默认值真正不同的只有 6 个开关 + F-20 强度档（WP-5 §4 总览），差异面被刻意压到最小。

smart 清单独立维护（§6），与 lite/full 正交，不得用 lite 之名裁剪 Smart 核心参数（WP-5 §3.2）。

### 1.4 变体派生（build/）

构建生成器职责：按清单展开模块 → 拼装单文件产物 → 注入文件头（版本三元组、档位后缀、源 commit 短哈希、共享段指纹）→ 产物内保留机器可读锚点注释（variant + profile-hash）。构建约束：

- 开关表与服务定义必须展开为**顶层静态字面量**，不得变成运行时计算结果（Bettbox 提取阶段会直接失败，SRC-1004 §2.0 / SRC-1008 §1.1）；
- 只做块级拼装，**不做函数级裁剪**（tree-shaking 式引用分析在本项目无 CI 兜底时风险最高，WP-5 §2.4 已否决为现阶段路线；待 WP-14 基建成
