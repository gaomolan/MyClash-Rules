# ADR-003 规则集供应链与完整性

- 状态：研究建议（待所有者确认）
- 日期：2026-10-28
- 关联：WP-8 规则集分级（SRC-1011 §3）、WP-12 威胁模型（SRC-1015）、WP-13 许可证红线（SRC-1017 §1/§3）

## 背景

现行 38 个 rule-provider 全为 http+mrs、interval 86400，分级（WP-8 实测）：bett-rules via raw 34 个 A-、AWAvenue via jsDelivr 1 个 B、Emby/emos via jsdmirror 2 个 B-、cn_additional via 个人域名 353355.xyz 1 个 C。结构性事实：mihomo 的 rule-provider 与 geox 均不提供哈希/签名锚定，客户端对照单全收；HTTPS 只证明域名、不证明内容未被替换（WP-12 §0）。源端篡改可改道任意域名分流（T-01，可能性2×影响5=10 高；bett-rules 约 35 处 URL 派生自单一基址 ruleSetBaseUrl）。现行 rules-canary 只探活、不验内容指纹；meta-rules-dat 曾发布 10 个 0 字节 .mrs 静默失效，证明「HTTP 200 ≠ 内容可用」。冷启动 bundle 兜底覆盖 33/38，缺失 5 个；Emby bundle 内容与远端原文不等价（隐性语义替换）。

## 选项

- **甲：维持现状**。raw 单源 + 探活巡检。
- **乙：官方源优先 + 内容指纹巡检 + 分级处置**。不自建镜像；巡检升级为内容基线（sha256 指纹 + 条目数/体积基线）；按分级逐项处置弱环；浮动锚收紧。
- **丙：自建镜像/打包分发规则集**。新仓托管规则集副本，用户只连自有源。

## 决定

采**乙**，丙明确否决。要点：

1. **禁止打包/镜像 GPL 数据文件**（丙的否决理由）：bett-rules/AWAvenue/meta-rules-dat/666OS 为 GPL-3.0，现行 URL 引用不触发分发义务；一旦入仓镜像，义务立即翻转（WP-13 红线），且镜像引入「内容时效与上游不一致」的新漂移面。个别例外（如 cn_additional 内联处置）须逐项过 WP-13 复核，不得类推。
2. **巡检升级**：rules-canary 增加内容指纹基线——每集记录 sha256 与体积/条目数量级，指纹突变或体积异常（如归零）告警；「探活通过但内容异常」按故障处理。此为在内核不提供完整性锚定的前提下，唯一现实可行的完整性补偿。
3. **分级处置**：C 级 cn_additional 优先内联或替换为可溯源等价物（DEP-009）；B- 级 Emby/emos 随模块化保留独立换源点、文档明示 bundle 不等价；旧线（custom/旧 smart）的 bett 基址与图标/Emby 通道跟进切换 raw，消除 jsdmirror 敞口（R-002 缓解项）。
4. **浮动锚收紧**：geox 的 `release` 分支锚、external-ui 的 `releases/latest` 锚为全清单最松（T-08，中），在脚本默认值层面评估改钉版本或在文档中明示漂移面；健康检查单 URL（apple.com，T-11 中）维持但纳入同一巡检视野。
5. **首启兜底**：bundle 缺失 5 集与 provider 首次下载失败语义未明示（WP-8 U-1/U-2）列为待验证，不在本 ADR 内假定；发布说明中不得宣称「离线首启完整可用」。

## 后果

- 正面：完整性从「无校验」提升为「源端可审计的指纹基线 + 异常告警」；弱环按爆炸半径排序处置（cn_additional 虽评级最低但爆炸半径最小、处置成本也最低，先行合理）；许可证红线不被触碰。
- 负面：指纹基线需随源端正常更新滚动维护，巡检误报治理成为常态工作（以「条目数量级 + 关键域名抽查」辅助判读真更新与被篡改，基线更新须留痕）；raw 单源的可用性风险（源仓变更/删除）仍在，缓解靠巡检告警 + 备用源清单（WP-8 已登记替代源），不在本期建镜像对冲——此为已知接受的残余风险。
