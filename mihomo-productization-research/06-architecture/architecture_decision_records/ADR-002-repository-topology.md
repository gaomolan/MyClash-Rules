# ADR-002 仓库拓扑

- 状态：研究建议（待所有者确认；D-003 假设的评估结论，确认前不得执行）
- 日期：2026-10-28
- 关联：路线比较第二部分 T1~T4（route_comparison.md §2）、WP-12 可见性切换分析（SRC-1016 §4）、迁移风险（migration_risks.md）

## 背景

现仓同时承载四种角色：上游克隆镜像（122 文件中 96 个与上游逐字节相同）、发布面（三件套及 custom 线的订阅源）、自有资产托管（图标经 jsDelivr 锚本仓浮动分支）、个人实验室（combo 含 [Spark] 个人命名逻辑）。角色混杂产生两个已登记风险：R-004（严重，4×4=16：整体公开会带出个人逻辑与过期材料；直接转私有则图标匿名 URL 立即失效）与个人逻辑公开硬门禁（WP-12：combo 永不进入公开候选集）。D-003 将「新公开仓 + 旧仓转私有实验室」记为待评估假设，本 ADR 给出评估结论。

## 选项

- **T1 现仓原地演进**：一仓到底，靠 .gitignore/分支/目录约定隔离个人内容。
- **T2 新公开仓 + 旧仓转私有实验室**：公开仓只放可发布源码/产物/自有资产；旧仓保留 sync 与个人构建目标。
- **T3 双仓双轨长期并行**：新仓公开推广、旧仓保持现可见性继续自用。
- **T4 仅文档化不产品化**：现仓冻结为个人项目，只补文档。

## 决定

采 **T2**，但附**生效前置条件**（缺一不可，细化步骤与验证见 migration_risks.md 的 M-01~M-08）：

1. 自有图标先迁入新公开仓并回读验证；
2. 三件套与文档中的图标引用全量切换至新仓地址并实测；
3. 匿名（未登录）状态下从新仓实际拉取脚本与图标成功；
4. 新仓许可证卫生完成（脚本文件头补 MIT 声明、无许可数据源处置、禁止打包 GPL 数据文件）；
5. 上述全部通过后，才变更旧仓可见性为私有。

前置条件未齐时，事实状态保持 T1，任何人不得以「已决定 T2」为由提前切换可见性。

## 后果

- 正面：公开面许可证与内容可审计；个人逻辑的结构性隔离（不在同一仓即不会误推）；实验室保留 sync/精选/个人构建的全部现有工作流；发布获得 tag/校验和/回滚锚（修复 T-03 无版本锚问题的一部分）。
- 负面与代价：存量订阅 URL 一次性迁移（旧地址须保留过渡期，靠 GitHub 重定向 + 发布说明，见 migration_risks M-05）；双仓心智成本（以「公开仓=唯一发布面」的单向精选流对冲）；新仓冷启动无 star/索引（非目标，不以推广节奏衡量）。
- 次选与触发：T1 为 T2 前置未齐或公开意愿撤回时的回落位；T3 仅当「旧仓必须保持现可见性」成为硬需求时启用，并须接受个人逻辑同仓的常驻审计成本。

## 证据引用

- R-004 及其缓解原文（SRC-1003）：「资产先落公开仓再切换引用，最后才变更旧仓可见性」。
- WP-12（SRC-1015 T-03/T-06/T-07；SRC-1016 §4/§5）：无版本锚分发链、combo 敏感定性（使用习惯类、不含凭据、7 类扫描仅 1 误报且为合成夹具）、图标 jsDelivr 浮动锚与缓存不可控、四条发布硬门禁。
- WP-13（SRC-1017 §2/§4/§7）：单文件许可声明缺口、图标逐图标许可待确认、发布前 P0 处置清单。
- WP-1 基线（转引自 SRC-1004 §1.1 与项目台账）：现仓与上游逐字节相同文件占比 79%，公开面应发布自有资产而非上游克隆。
