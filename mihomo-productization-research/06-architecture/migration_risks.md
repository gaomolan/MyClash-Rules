# WP-15 迁移步骤级风险清单（推荐路线：代码路线 B × 拓扑 T2）

- 研究日期：2026-10-28
- 性质：执行前的风险预演；本阶段不执行任何迁移步骤（D-001）
- 适用前提：所有者确认 route_comparison.md 的总推荐后，本清单作为迁移执行顺序与验收门禁；顺序即依赖关系——**M-01~M-04 全部通过前，禁止执行 M-06（旧仓私有化）**（R-004 硬门禁顺序）
- 记法：每项含 步骤目的 / 风险 / 缓解 / 验证方式（须留痕，验证不过不得进下一步）

---

## M-01 自有图标先行迁入新公开仓

- 步骤目的：把脚本运行时依赖的自有图标（Claude/GitHub/Cloudflare 三枚）先落到新仓，使后续引用切换有目标、私有化有前提。
- 风险：迁移遗漏或文件损坏导致切换后图标空白（fail-soft，不影响代理功能但用户可感）；三枚图标的逐图标许可字段本轮未取得（Simple Icons 声明项目 CC0 ≠ 逐图标 CC0，SRC-1017 §4.1），迁入即构成再分发，许可未明状态被带入公开仓。
- 缓解：迁入前以 sha256 与现仓文件逐一对账；许可待确认状态在新仓 NOTICE 中明示，不默示背书；商标指示性使用问题列入 WP-13 §6 法律清单随迁入一并处置。
- 验证方式：新仓三文件 sha256 与现仓一致；NOTICE 文件存在且含待确认条目。

## M-02 图标重复文件收敛

- 步骤目的：`Cloudflare.svg` 与 `Cloudflare-v2.svg` 经实测字节完全一致（E4），不同脚本分别引用；迁入新仓前收敛为单一文件名单一引用名，避免把历史偶合带进新仓资产面。
- 风险：收敛时改错引用名导致某一脚本图标失效；上游继承图标（38 png + 继承 svg）逐项来源未标注、AGENT.md 的 png/svg 配对约定与现状已不符（SRC-1017 §4.2/4.3），顺带「整理」继承图标会把范围扩到不可审计区。
- 缓解：本步只处理自有三枚与 Cloudflare 重复对；继承图标整体不迁（新仓图标面只含自有资产 + 脚本运行必需的最小集），避免来源不可证资产进入公开仓。
- 验证方式：全仓 grep 旧文件名零命中；三件套在隔离环境跑通生成、图标 URL 逐一 HTTP 200。

## M-03 脚本与文档的引用切换

- 步骤目的：将三件套 iconBaseUrl、README 与文档中的图标/脚本引用从现仓地址切换至新仓地址。
- 风险：引用点遗漏（脚本内派生地址不止一处：图标基址、ASN 基址等由 base 派生的链条）；切换与 M-06 顺序颠倒（先私有化后切换）直接造成线上图标失效——这是本迁移中唯一「顺序错误即产生用户可见故障」的点。
- 缓解：切换前以 grep 穷举现仓域名/基址引用清单逐项销账；严格执行顺序 M-01 → M-03 → M-04 → M-06；切换以单独 commit 落地以便回退。
- 验证方式：引用清单销账表全绿；切换后隔离环境生成配置中无现仓域名残留（个人 overlay 引用除外，其不随公开产物迁移）。

## M-04 匿名拉取验证

- 步骤目的：在未登录、无缓存污染的条件下，实测新仓的脚本与图标可被匿名拉取（模拟真实用户客户端行为）。
- 风险：jsDelivr 缓存时点不可控（WP-12 §4），验证时命中旧缓存给出假阳性；raw 与 jsDelivr 两通道状态不一致（本项目已有「两缓存层互相矛盾」的实测教训，仓库现状以 GitHub API 为准）。
- 缓解：验证同时走 raw、jsDelivr 两通道 + GitHub API 内容回读三方对照；jsDelivr 通道执行 purge 后复测；验证时间点记录在案，私有化前 24h 内再复验一次。
- 验证方式：三方内容哈希一致；匿名 HTTP 状态全 200/206；复验记录留痕。

## M-05 订阅地址变更与存量用户影响

- 步骤目的：公开产物订阅地址由现仓切换至新仓，存量用户（含维护者主力机/测试机与少量分享用户）平滑迁移。
- 风险：现行分发锚为浮动分支、无 tag/校验和（T-03），用户侧无法区分新旧代次；GitHub 改名/迁移的重定向在旧名被抢注时失效（T-07，已有 2026-10-27 改名实证）；用户不读发布说明时长期停留在旧地址，旧仓私有化后其订阅直接失效且无提示。
- 缓解：新仓发布即启用 tag 钉版 + 分支版双地址（WP-5 §6.3）；旧仓在私有化前保留一个过渡发布周期，期间旧地址文件头注入迁移提示注释；发布说明给出迁移三步（换链接 → 复核开关页 → 自检组数与 DNS）；过渡期长度由所有者拍板（建议不短于一个 rules-canary 巡检稳定周期，且在 ISSUE/支持面可观测到旧地址请求衰减后再执行 M-06——无遥测时以固定期限 + 主动通知代替观测）。
- 验证方式：维护者双机先行切换实测（主力机 custom 线、测试机 smart 线各一）；过渡期满且 M-04 复验通过，才解锁 M-06。

## M-06 旧仓可见性切换（转私有）

- 步骤目的：完成 T2 的实验室定位：旧仓转私有，保留 sync、精选评审与个人构建目标。
- 风险：除图标外仍有未盘点完的匿名引用指向旧仓（文档外链、star-board 等关联项目的引用——2026-10-27 改名清扫时 resource-box 仓因 App 无访问权未盘点，此缺口仍在）；切换后 GitHub App 对私有仓的授权范围变化可能影响既有自动化读取。
- 缓解：切换前做最后一輪全量引用扫描（含关联仓库清单逐仓确认，resource-box 须先解决 App 授权再盘点）；切换选在低使用时段并预告；切换后立即以匿名身份复测 M-04 全部条目 + 以维护者身份复测 sync 与脚本读取链。
- 验证方式：匿名复测全绿（新仓面）且旧仓匿名访问按预期拒绝；维护者通道（App/浏览器登录态）读写正常；异常时回滚动作 = 立即恢复旧仓可见性（可见性切换本身可逆，这是不把 M-06 放在最后的底气，但回滚窗口内已失效的用户订阅不会自动恢复，需在发布说明中预置说明）。

## M-07 sync workflow 的处置

- 步骤目的：现行 sync-myclash.yml 每 4h 自动拉上游 + 拼接 customPatch 直推、在主力机订阅链上无门禁（R-005/T-04）。迁移后 sync 只应存在于实验室仓，且产物落候选分支而非发布面。
- 风险：处置期间 sync 中断或误推：若先停 sync 再建候选链，主力机 custom 线更新出现空窗；若候选分支机制未建好就切换落点，自动产物可能误入公开仓候选集（公开面污染）；GitHub App 无 workflows 权限，workflow 文件变更须所有者手动在网页完成（既有权限边界），自动化代劳不可行。
- 缓解：处置顺序为「先加固、后移位」：先在现行 sync 上补 Validate 断言（4 个上游内部标识符存在性 + node --check + 合成冒烟 + 文件头记上游 commit hash，WP-12 增补项），运行稳定后再随实验室定位改为候选分支落点；workflow 文件由所有者手动更新（助手备好内容）；custom 线在主力机的订阅地址过渡期不变，避免与 M-05 的地址迁移叠加变更。
- 验证方式：加固后至少两个 sync 周期（8h）Validate 全绿且有一次「故意构造上游标识符缺失」的负向演练（在实验室环境）确认断言生效；落点切换后候选分支收到自动提交、发布面零自动提交。

## M-08 许可证卫生补齐

- 步骤目的：新仓公开发布前补齐 WP-13 P0 清单：脚本文件头补 MIT 许可声明；无许可数据源（emos-proxy-rule 无 LICENSE、353355 cn-additional 不可溯源）取得许可或替换/内联处置；新仓立规禁止打包 GPL 数据文件。
- 风险：处置动作本身改变脚本行为（如替换 cn_additional 影响 QUIC 豁免子句的行为面）；文件头声明与仓库根 LICENSE（上游 AIsouler 版权原文）之间的署名关系表述不当。
- 缓解：数据源替换逐个走 WP-8 复评（行为等价性以规则覆盖对比验证，不凭来源名气）；文件头声明措辞与 WP-13 §7 建议对齐，存疑处保留法律清单条目不自行发挥。
- 验证方式：WP-13 矩阵 LIC-01~20 逐项状态更新留痕；替换项有替换前后规则覆盖差异报告。

## M-09 构建化迁移期间的双轨发布（代码路线 B 阶段 2）

- 步骤目的：从手写三件套过渡到构建生成产物期间，保证发布不中断、行为不漂移。
- 风险：构建产物与手写版在过渡期出现未声明差异（整输出对比必有合法差异如指纹行，须用 WP-5 §5 的分域对比而非整文件哈希，否则误报淹没真差异）；构建脚本缺陷把错误同时带进双档产物（单源的代价：故障也单源）。
- 缓解：过渡期双轨并行：构建产物先以「影子发布」与现行手写版跑同一夹具做 L1 分域对比，连续若干发布周期差异集为空才切换发布面；切换后手写版冻结一个周期作为回滚源；发布门禁执行「未跑三级检查或未 PASS 不得发布」（WP-5 §5）。
- 验证方式：影子期对比报告留痕；切换周期的发布记录含三级检查输出与共享段指纹。

## M-10 个人构建目标（combo）的迁移

- 步骤目的：combo 从「现仓内的第五个文件」变为实验室仓的私有构建目标（overlay + 私有 manifest），与公开仓选材流程物理分离。
- 风险：迁移过程中个人 manifest/overlay 被误纳入公开仓候选集（本迁移中保密等级最高的单点）；构建脚本若设计为「遍历目录生成全部目标」，新目标文件落错目录即自动进发布面。
- 缓解：构建脚本采用**显式目标白名单**（发布面只构建 lite/full/smart 三个登记目标，未登记目录直接报错）；overlay 只存实验室仓；公开仓选材评审清单含「个人命名扫描」（[Spark]/机场名/个人前缀模式匹配，WP-12 敏感扫描 7 类形态可直接复用为检查项）。
- 验证方式：对公开仓产物做个人命名扫描零命中（作为每次发布的常设门禁，而非迁移期一次性动作）；故意放置未登记目标目录时构建应报错（负向演练一次）。

## M-11 文档与过期材料处置

- 步骤目的：现仓 159KB AGENT.md 为上游旧快照、与现状双向脱节；新仓文档面只带现行有效的 README/构建文档/发布说明，旧材料随实验室仓封存。
- 风险：把过期材料误带入新仓造成新用户误导；或把仍有效的运维记录（如巡检说明、开关清单）误判为过期而丢失。
- 缓解：文档迁移逐份列清单标注「迁移/重写/封存」三态；封存项只留实验室仓并在文件头加「历史快照、勿据此操作」标注。
- 验证方式：清单销账；新仓文档全量通读一遍无指向旧地址/旧行为的陈述（与 M-03 引用扫描合并执行）。

## M-12 Smart 实验线的迁移标注

- 步骤目的：smart 变体随迁移进入「独立实验线」定位（ADR-004）：独立产物、独立发布说明、参数基准唯一化。
- 风险：迁移时顺手把 smart 参数从社区模板「顺手更新」引入未核参数（静默失效）；用户把实验线产物误作主线导入（其 type:smart 在官方内核不可用，失败形态未验证）。
- 缓解：smart 参数集与 lux5am fork 源码标签逐项对账表随迁移建立并入库；实验线产物文件头与发布说明含「需非官方内核」显著标注。
- 验证方式：对账表零未核条目；标注存在性检查纳入发布门禁清单。

## 顺序总览与一票否决点

```
M-01 图标迁入 → M-02 重复收敛 → M-03 引用切换 → M-04 匿名验证 ┐
M-08 许可证卫生 ────────────────────────────────────────────────┤
M-11 文档处置 ──────────────────────────────────────────────────┤ 全部通过
M-07 sync 加固（可与上并行，但落点切换须在 M-06 前完成验证）────┘
        → M-05 存量过渡期 → M-06 旧仓转私有 → M-10/M-12 实验室侧收尾
        → M-09 构建化影子期 → 构建产物接管发布面
```

一票否决点（任一命中即暂停迁移、回滚当前步）：
1. M-04 匿名拉取任一通道哈希不一致；
2. M-10 个人命名扫描在公开仓产物中命中；
3. M-07 负向演练中 Validate 未能拦住构造的坏输入；
4. M-09 影子期出现未声明的行为差异。
